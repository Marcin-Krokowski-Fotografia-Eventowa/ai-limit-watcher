Co wpada do okna kontekstu Claude Code

Kontekst to materiał roboczy, który Claude Code widzi w bieżącej sesji. Trafiają do niego instrukcje, historia rozmowy, czytane pliki, odpowiedzi modelu i wynik narzędzi. Reguły projektu, pamięci, skille i hooki mogą dorzucić treść jeszcze przed pierwszym promptem.

Dlatego sesja rośnie także bez jednego ogromnego polecenia. Lista katalogów, szerokie wyniki wyszukiwania i długi log testów mają sens tylko wtedy, gdy pomagają podjąć następną decyzję. W przeciwnym razie jadą z rozmową dalej.

Dlaczego późne tury bywają cięższe niż początek

Każda kolejna tura opiera się na historii, która nadal jest potrzebna w sesji. Na początku masz krótki brief i kilka plików. Później dochodzą wcześniejsze decyzje, edycje, logi i powtórzone dochodzenia.

Praktyczne pytanie nie brzmi: „jak napisać najkrótszy prompt?”. Lepiej zapytać: „co musi być dostępne przy następnej decyzji?”. Ta odpowiedź powinna być krótka i nazwana.

Kiedy użyć /clear, a kiedy /compact

/clear przy nowym temacie

Gdy przechodzisz z błędu CSS do tekstu marketingowego, stara rozmowa jest głównie bagażem. Zacznij czystą sesję i nazwij nowy cel. Jeśli przydaje się jedna wcześniejsza decyzja, przenieś ją do nowego promptu zamiast całej dyskusji.

/compact przy ciągu dalszym jednego długiego zadania

Kompresja streszcza rozmowę, aby można było dalej pracować nad tym samym. Zanim ją uruchomisz, nazwij priorytet: cel, przyjęte decyzje, ważne pliki, wykonane kontrole i aktualne ryzyko. Dokumentacja Claude Code nazywa to kompresją z ukierunkowaniem.

Żadne z tych poleceń nie powiększa limitu planu. Zmieniają tylko to, co bieżąca sesja niesie dalej.

Czytaj mniej repo i trzymaj logi przydatne

  • Zacznij od wąskiego wyszukiwania po nazwie pliku, symbolu albo widocznym fragmencie tekstu.
  • Najpierw otwórz najmniejszy plik lub zakres, który może odpowiedzieć na kolejne pytanie. Rozszerzaj dopiero wtedy, gdy wynik to uzasadni.
  • Proś o skupiony wynik polecenia, na przykład nazwy nieudanych testów, zamiast pełnego logu budowania.
  • Przy dużym researchu zachowaj końcowe podsumowanie z dowodami, a surowe szukanie zostaw w jego własnym kontekście.
  • Niepowiązane usprawnienia zapisuj jako Later. Nie dokładaj ich do bieżącego zadania tylko dlatego, że są obok.

Jedna lokalna próba, nie obietnica

Zrzut Statystyk w AI-limit-watcher pokazuje jedną próbę z siedmiu dni na Macu autora. W tej próbie 74% tokenów trafiło do wywołań z kontekstem powyżej 200 tys. Późna tura użyła 526 tys. tokenów wobec 68 tys. na początku. To sygnał, żeby sprawdzić własne nawyki, nie wynik, którego każdy użytkownik Claude Code powinien oczekiwać.

AI-limit-watcher pokazuje, gdzie zeszło użycie i kiedy limit wraca. Sama aplikacja nie zwiększa limitu ani nie zmniejsza zużycia tokenów.

Skopiuj skill context-saver

Ten mały skill jest dla prawdziwego zadania, które zaczyna zmieniać się w szerokie dochodzenie. Skopiuj go do folderu context-saver albo pobierz gotowy folder.

---
name: context-saver
description: Keep a substantial coding or research task focused when it risks broad repository reads, long tool output, or an overloaded session. Do not use for a simple one-file edit.
---

# Context Saver

Work on one user task at a time.

- Start with a narrow search and the smallest files or ranges that can answer the next question.
- Read the full repository or full logs only when earlier evidence shows they are needed.
- Do not add adjacent improvements. Record them as `Later`.
- At the end of a stage, write a short handoff: goal, decisions, files, tests, risks, and one next step.
- Do not promise a percentage reduction in context or token use.
